# AIMFA — MFA for AI Agents

> A zero-trust checkpoint for AI agents. Every action an agent takes must prove **what the agent is**, **what it holds**, and **that it is behaving normally**. Risky actions also need a **human's** approval.

AI agents now hold real credentials and act on their own. Human MFA (password + phone code) doesn't fit them: an agent has no phone, no fingerprint, and never "logs in". Most agents today simply carry a **static API key** that never expires and works for anyone who steals it. AIMFA replaces that key with four layered checks. All of them are enforced by a gateway that sits between the agent and every tool it uses.

| Factor | Question | Mechanism |
|---|---|---|
| **Is** | Is this the exact agent we approved? | **Attestation**: hash of code + system prompt + tool manifest + model, compared to a registered golden value |
| **Has** | Is it holding a valid, *bound* credential? | **Short-lived scoped tokens** (15 min, least privilege) bound to the agent's private key with **DPoP**. A stolen token alone is useless. |
| **Does** | Is it behaving like itself? | **Behavioral risk score**: out-of-profile access, scope violations, exfiltration patterns. High risk triggers step-up, then revoke + quarantine. |
| **Human** | Should this risky action happen? | **Step-up approval**: push notification to a human, who approves with their own TOTP code, bound to that exact action |

Every decision lands in a **hash-chained, tamper-evident audit log**.

## Architecture
```
 Launcher ──attest──▶ CONTROL PLANE :8000  (registry · attestation · token service · revocation
 (measures agent,      · approvals + push + TOTP · risk monitor · audit chain · admin API)
  makes keypair)              ▲   │ push (ntfy)
     │ starts                 │   ▼
 AI AGENT ──token+DPoP──▶ GATEWAY :8100 ──internal secret──▶ MOCK RESOURCES :8200
 (TAMU AI or scripted)    verify → DPoP → replay → scope      files · email · bank · db
                          → risk → tier → allow/deny/pending
 Dashboard :8501 (Streamlit): agents · tokens · risk · approvals · audit · attack lab
```

## Quickstart
```bash
python -m venv .venv
.venv\Scripts\activate          # Windows   |  source .venv/bin/activate  (macOS/Linux)
pip install -e ".[dev]"
copy .env.example .env          # Windows   |  cp .env.example .env
# edit .env: set the secrets, NTFY_TOPIC, and the TAMU_AI_* values
pytest                          # run the test suite
python scripts/check_tamu_ai.py # verify the LLM connection (optional)
python scripts/run_demo.py --reset   # start everything (available after Phase 5)
```

**External services** (everything else is local and fake):
- **TAMU AI** API key: optional. Scripted agents work without it.
- **ntfy.sh** topic: free, no account. Optional, since approvals also work in the dashboard.
- An **authenticator app** for the human approver.

## Demo & evaluation
Each attack runs twice: once in **baseline** mode, where the agent holds a static API key, and once in **AIMFA** mode.

| # | Attack | Baseline | AIMFA blocks via |
|---|---|---|---|
| A1 | Tampered agent prompt/code | succeeds | attestation |
| A2 | Stolen token used elsewhere | succeeds | DPoP key binding |
| A3 | Replayed request | succeeds | DPoP `jti` replay cache |
| A4 | Prompt injection → steal secrets + email out | succeeds | scope + monitor + human step-up |
| A5 | Unauthorized wire transfer | succeeds | human step-up |
| A6 | Expired / finished-task token | succeeds | TTL + revocation |
| A7 | Scope escalation | succeeds | token service policy |
| A8 | Audit log tampering | undetected | hash chain |
| A9 | Approval without TOTP / reused approval | n/a | TOTP + action binding |

## Limitations (by design, for a course prototype)
- **Simulated attestation.** There is no TPM/TEE, so trust is rooted in the launcher.
- **Localhost trust.** Services trust each other via shared secrets, not mTLS.
- **Prompt injection is *contained*, not prevented.** An injected agent can still misbehave inside its scope.
- **Heuristic monitoring.** It produces false positives and negatives.

See [docs/THREAT_MODEL.md](docs/THREAT_MODEL.md).
